# Architecture

The interface is implemented in Flutter with Material 3 enabled. It uses ColorScheme roles for light and dark surfaces, native Material controls for keyboard interaction, a persistent sidebar at large sizes, and a compact rail at smaller sizes. Windows window management is handled by window_manager. libmpv, through media_kit, handles H.264, H.265 and HLS playback.

## Data flow

1. The client loads the compatibility protocol shipped with the user-provided Windows 1.1.5 client.
2. An MD5-derived discovery hostname resolves to a configuration endpoint on port 7862. The discovered service address is cached and revalidated at subsequent launches.
3. HTTP requests use the original timestamp, APPID, system and Authentication headers. Signed-in requests include X-Token. The Authentication field is base64 text encrypted with AES-CBC. Responses can be plain JSON or an RSA-wrapped AES-CBC JSON envelope. POST and DELETE bodies use the original RSA public-key and AES-CBC envelope, including Unicode account and comment fields.
4. Listing, search, details and danmaku use the /pc endpoints. Requests have timeouts and surface server errors.
5. The playback adapter handles direct HTTP media URLs, the known playaddr/lua/v4/get provider template, and the original mao authentication flow. It reads the known Lua template's constants as data and implements the specified request; it never executes remote Lua. Unknown scripts and account-restricted sources show an explicit error.

The compatibility data in assets/protocol.json is embedded in the original public desktop client. It is a protocol dependency, not a personal login credential. It can change if the service changes its desktop protocol.

## Local state

Theme mode, playback preferences, favorites, follows and up to 150 recent play records are stored in the application's shared_preferences namespace. Renaming migrates only the previous 0.1.0 client's local preferences. This app does not read the original Electron application's account or token. Progress is saved every 10 seconds, on playback navigation, and before a normal window close.

AccountSession restores a DPAPI-encrypted token from account.dpapi using a small native Flutter method channel. CryptProtectData and CryptUnprotectData bind it to the current Windows user and machine. Passwords are never persisted. Auth error codes invalidate the current token. Account history uses /pc/history separately from local history; sync failures leave local progress intact and expose a status icon in the player. Comments use the original list, sublist, create and likes endpoints, with a user-entered image challenge if required.

SeasonSchedule fetches the entire selected quarter from the public Bangumi subject search, respecting the server-returned pagination size. Remaining pages load in groups of three. The current calendar contributes explicit weekdays and continuing series. The displayed quarter is independent of CLICLI availability: no annual catalog indexes or per-title searches run during timetable loading. Only selecting an entry invokes CatalogSchedule.resolve, which searches the selected name and aliases, checks exact normalized titles, season and premiere year, and requires nonempty episode sources. Search pagination stops on exhaustion or repeated pages. Overly broad queries and network failures surface as errors rather than claiming absence. A successful lookup opens the real catalog detail; a completed lookup without a playable match shows exactly CliCli没有该影片. Public quarter metadata is cached for 30 minutes and individual lookups for 15 minutes, including missing results. Failed lookups are not cached. Catalog reads remain serialized with a 1200-millisecond interval and rate-limit retries after 15/30 seconds. CLICLI tokens are never sent to public metadata services.

AiringSchedule supplements the quarter with paginated public AniList broadcast instants. It matches exact normalized native/Chinese/English titles with season numbers preserved; ambiguous titles keep their original metadata. Previous-quarter entries are also queried for continuing works. Unix timestamps convert to the computer's local time and weekday, including midnight rollover; each card displays its UTC offset and a source tooltip. Missing times appear as --:--. Secondary-source errors do not remove the complete Bangumi catalog. Account tokens are never sent to AniList.

Player controls and the danmaku composer live inside a fixed 16:9 video frame with a dark gradient independent of the app theme. Mouse movement, pause and keyboard focus reveal them. Seek preview commits on release. Text-field focus disables the ancestor playback shortcuts. Danmaku timestamps are doubles, missing/invalid values are discarded, and constant-speed lanes limit simultaneous content. Once duration is known, ten-minute ranges load the whole episode so the list includes later timestamps. Sending uses the captured current video time with the original numeric type, size and ARGB color fields; authentication and user-entered captcha challenges follow the original protocol. Native mpv warnings only become playback errors after a stalled interval.

The compact danmaku composer sits in the center of the playback toolbar after the time display, bounded to 340 logical pixels. Below 850 pixels of video width it moves to a second row, bounded to 380 pixels. A stable global key preserves draft text and focus when moving between rows. Playback speed and quality are grouped into one menu below 1240 pixels to leave composer space. Volume uses a 140/180 pixel slider. Three seconds without pointer movement in a normal window, or two seconds in fullscreen, hides the playing video's controls and cursor, including when the cursor rests on the toolbar; menus, seeking, errors and text editing keep controls visible. The player episode panel uses three equal columns; detail-page density remains responsive. Timetable cards use three columns at the normal desktop width, falling to two or one on narrow layouts. Favorite badges use a heart; followed badges use a bookmark.

History uses nullable watch dates instead of a fabricated year-2000 timestamp. ISO offsets and Unix seconds/milliseconds are parsed to local time. Both local and account lists group actual dates, order newest first, show the watch clock separately from playback progress, and place missing dates in an unknown group. SessionStore is injectable so automated UI tests cannot restore or mutate the daily account session.

Account progress uses a provider-supplied duration, then a local duration cache keyed by video ID, source and episode, then background MediaDuration reads with two workers. The cache persists up to 300 measured episode durations independently of the latest watch entry. MediaDuration reads bounded HTTP HLS playlists with the playable headers, follows relative master variants, and sums finite VOD EXTINF entries only when EXT-X-ENDLIST exists. It never starts playback or downloads video segments. Generation checks reject obsolete results after refresh or account changes. Missing or unsupported durations show an empty track with an explanatory tooltip instead of a fabricated percentage.

WindowFullscreen uses a small native method channel rather than the window_manager fullscreen branch that can skip resizing an already-frameless window. The runner saves styles and WINDOWPLACEMENT, uses the monitor rectangle instead of the work area, fills the Flutter child view, and restores normal or maximized placement on exit. Geometry diagnostics expose actual window, client and monitor rectangles to the integration test.

AppTheme generates Material 3 semantic roles from the selected accent. Preferences persist the accent and danmaku display settings. Noto Sans SC is bundled at actual 400/600/700 weights to provide consistent vector outlines; Flutter retains its own text rasterizer and Windows DPI support.

CoverCache prefers the catalog cover URL and caches successful image bytes in the application cache directory. On failure it queries the public Bangumi catalog with the public title and accepts an exact normalized title plus season match, rejecting conflicting years. Ambiguous candidates remain placeholders. Catalog content and ratings always remain from CLICLI.

CoverLoader limits concurrent work to six requests, shares in-flight loads, validates image decoding before caching, retries transient downloads once, and evicts failed results so subsequent attempts can recover. Empty original URLs also use the title fallback. Placeholder icons offer a cover retry. Verified aliases cover BLEACH (the original catalog incorrectly labels the 2004 series as 2008), Attack on Titan's fourth/final season and separate Part.2, and Jujutsu Kaisen's Hidden Inventory/Shibuya second season. Other conflicting years and ambiguous results are still rejected.

## Verification

Unit and widget tests cover independent RSA/AES fixtures, request headers, Unicode search encoding, provider resolution, persistence, corrupted local data, cover matching, desktop and minimum-size layouts, favorites, follows and large episode lists.

The Windows integration test connects to the real service and tests catalog navigation, search, 1080p playback, seeking, switching episodes, fullscreen, history resume and keyboard navigation. It records screenshots in docs/screenshots. Because these tests use the live service, future failures can also indicate endpoint or content changes.


## Installers and updates

Inno Setup 7 builds a per-user Windows x64 installer with a stable AppId, optional desktop shortcut, Start menu entry and uninstall metadata. The default destination is LOCALAPPDATA/Programs/CiliCiliWinRev. Upgrades reuse the chosen destination; uninstallation removes installed files and shortcuts but does not delete AppData preferences or DPAPI sessions. The package contains libmpv and required Visual C++ runtime DLLs.

AppUpdates uses a separate unauthenticated HTTPS client to GET api.github.com/repos/WhiteBr1ck/CiliCiliWinRev/releases/latest, with a 20-second timeout. Automatic checks run once at startup; the preference can disable them while manual checks remain available. Numeric major/minor/patch comparison rejects invalid and prerelease tags. An update requires exactly one CiliCiliWinRev-VERSION-windows-x64-setup.exe asset from that repository's GitHub release download path. Drafts, prereleases, missing installers, rate limits and network failures have distinct states; 404 means there is no published release. There is no background executable replacement. The user opens the installer download in the external browser and runs the installer. A startup update dialog is deferred when a detail or playback route is active. Tests inject HTTP fixtures and an in-memory SessionStore; the public live update endpoint is also read in the Windows smoke test.


## Application shutdown (0.6.1)

The close listener hides the window immediately and guards against duplicate close events. PlayerPage.shutdown cancels persistence and UI timers, captures the current episode position, awaits local history writes, and enqueues any account progress without starting another HTTP request. AccountHistorySync serializes durable preference writes; queued entries are partitioned by a SHA256 fingerprint of the session token, never by a plaintext token. Successful sends acknowledge only the exact queued entry, so newer positions remain pending. The queue is retried after restoration of the same login session. An account change cannot send another session's progress.

After persistence, ApplicationExit posts a private window message that calls ExitProcess(0). This deliberately bypasses synchronous Flutter engine/video plugin destruction: an isolated baseline close reproduced a 10.9-second delay and 0xC000041D process exit, and disposing the player before WM_QUIT still left a seven-second teardown failure. The operating system releases the process's media threads, handles and graphics resources after saved application state is safe. This exit path applies only to closing the whole app; ordinary player navigation continues to call Player.dispose. A separate Release-mode probe verifies normal exit and the final local/outbox values while cloud requests never complete.

Release attachments now contain only the versioned Windows x64 installer. Package directories remain local build staging for Inno Setup; ZIP and checksum attachments are not produced by the release build scripts.
